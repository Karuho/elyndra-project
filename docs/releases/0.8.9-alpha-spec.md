# Elyndra 0.8.9-alpha — Controlled Online Gateway specification

## Post-Phase-4 clarification: rejected HTTP status

A final rejected initial status is terminal, non-resumable and audited only with integer status/class
and bounded normalized hosts. Its body is unread and a proven empty partial without strong ETag is
removed. Audit JSON supplies persistence under schema 50; history is not reconstructed.

## Phase 4 implementation addendum

The post-Phase-4 integration correction separates deterministic preview, persisted plan approval and
foreground CLI execution. Persistent configuration remains unable to enable networking. Only an exact
CLI execute/resume command receives an ephemeral capability bound to operation and immutable plan;
normal application and web composition remain offline. Schema stays 50.

Phase 4 completes supervised acquisition of the pinned official language bundle: closed descriptor,
Phase 3 manifest/asset downloads, offline archive validation, private preparation and a distinct exact
approval for registry installation. It adds no scheduler, autoupdate, telemetry, authentication,
arbitrary URLs or executable bundle semantics. Web observation and local install controls do not start
network work; download execution remains foreground CLI-only. Tests use synthetic data and no public
host. Schema remains 50 because existing gateway operations represent the new install plans.

## Phase 3 implementation addendum

Phase 3 adds standard-library HTTPS transport, DNS/SSRF and peer pinning, bounded HTTP/redirect
handling, streaming storage, verification, cache/quarantine, cancellation, strong-ETag resume and a
global foreground lock. Runtime construction and read-only operations remain socket-free. Execution
requires the Phase 2 authority conjunction and consumes a new exact approval.

Only controlled loopback dependencies were used for validation. GitHub and the public Spanish Core
release were not contacted. The language-pack repository is currently not anonymously accessible, so
real acquisition remains blocked. No bundle parsing/install, scheduler, autoupdate or telemetry is
included.

## Phase 2 implementation addendum

Phase 2 resolves the former human decisions with owner-approved pinned values and fixed policies.
It supersedes the earlier proposed schema shapes below with the six role-specific tables named in
the Phase 2 brief. Existing `ApprovalStore` and `AuditRepository` replace the proposed parallel
approval and history tables.

This phase has no transport implementation and opens no sockets. Online mode alone grants no
authority: the global switch, account preference, immutable plan and single-use approval are all
required. The official source is planned only. There is no telemetry or automatic update behavior.

## Objectives

- Add one deny-by-default broker for explicit acquisition of pinned public artifacts.
- Support only HTTPS HEAD/GET and one active global foreground download.
- Keep account preference, download approval, install approval and enablement distinct.
- Protect every resolution/redirect against SSRF and rebinding.
- Stream bounded bytes through `.part`, hash, verify and atomically finalize.
- Reuse the 0.8.8 Spanish Core bundle as the first official integration.
- Preserve CLI/web parity, account isolation, audit privacy and model/tool separation.

## Non-objectives

No general browser, arbitrary URL fetch, private resource/authentication, GitHub API client, proxy,
cookies, telemetry, update checker, marketplace, silent/background download, startup traffic, model or
skill network tool, runtime search, remote evidence retrieval, automatic install/enable, language-pack
schema change or bundle-schema change.

## Binding product decisions

The 25 decisions in the owner brief are normative. In particular, online mode is inert until an exact
foreground action and approval; models never acquire network authority; URL/size/SHA-256 are fixed;
download and installation consume different approvals; only `official-pinned` and `user-pinned`
sources exist; cache is public/shared while preference, approvals and history are private; target
root/vault schema is 50; packs/bundles remain schema 1 and skills remain 102.

## Architecture and contracts

`docs/ONLINE_GATEWAY.md` is the normative component and flow design. Runtime implementation is divided
into `online_gateway/{models,policy,approvals,sources,transport,downloads,audit,errors}.py` plus
`language_packs/remote.py`. `OnlineGatewayPolicy` is pure; `NetworkPermit` is opaque and single-use;
`TrustedSourceRegistry` holds immutable revisions; `RemoteArtifactDescriptor` freezes identity;
`GatewayTransport` alone may open network connections; `DownloadManager` owns state/files/locking;
`GatewayAudit` allowlists privacy-safe facts; `LanguageBundleRemoteService` hands verified local files
to the unchanged local `LanguageBundleService`.

Elyndra owns all authority. Transport is injected only into the gateway composition root and must not
be reachable from model, tutor, auditor, planner, cognitive-executive or skill objects.

## Proposed schema 50

The migration is forward-only, transactional and role-specific from exact schema 49.

### Root database: shared public metadata

`online_gateway_sources`:

| Column | Contract |
|---|---|
| `id` | integer primary key |
| `public_id` | source-family text, at most 64 |
| `source_type` | `official-pinned` or `user-pinned` |
| `revision` | positive integer; unique with public ID |
| `display_name` | bounded text, at most 160 |
| `repository_identity` | bounded metadata, at most 200 |
| `status` | `active`, `disabled`, `superseded` |
| `descriptor_json` | canonical bounded JSON, at most 64 KiB |
| `descriptor_sha256` | 64 lowercase hex |
| `reviewed_by` / `reviewed_at` | explicit local review provenance |
| `created_at` / `updated_at` | UTC ISO timestamps |

Indexes: unique `(public_id, revision)`, lookup `(status, source_type, public_id, revision DESC)` and
unique active revision per `public_id`.

`online_gateway_downloads`:

| Column group | Columns |
|---|---|
| Identity | `id`, unique `public_id`, `source_id`, `source_revision`, `artifact_id`, `artifact_version`, `descriptor_sha256` |
| State | `download_state`, `verification_state`, `installation_state`, `enablement_state` |
| Integrity | `expected_size`, `received_size`, `expected_sha256`, `observed_sha256`, `etag`, `last_modified` |
| Storage | `partial_relpath`, `final_relpath`, `quarantine_relpath` |
| Network facts | `method`, `redirect_count`, `remote_host_sha256`, `remote_ip_class='public'` |
| Ownership | `initiating_account_public_id` for routing only; no account content |
| Diagnostics | `error_code`, bounded `error_detail`, `created_at`, `approved_at`, `started_at`, `finished_at`, `updated_at` |

Checks enforce enumerated states, non-negative bytes, 64-hex hashes, safe relative paths, method
HEAD/GET and a maximum bounded detail. Indexes: `(download_state, updated_at)`,
`(descriptor_sha256, verification_state)`, `(initiating_account_public_id, created_at DESC)` and a
partial unique index allowing only one row in `approved|connecting|downloading|verifying` globally.
The file lock remains authoritative across processes; the index is defense in depth.

### Account vault: private consent and history

`account_online_preferences` has one row per vault: `id`, `mode` (`local` or `restricted_online`),
`changed_by`, `created_at`, `updated_at`. Default is `local`. No proxy/private mode exists.

`account_gateway_approvals` stores `public_id`, `operation` (`download`, `resume`, `install`, `enable`,
`cancel`), root operation public ID, descriptor hash, approval-secret hash, request fingerprint,
`status` (`pending`, `consumed`, `expired`, `cancelled`), `expires_at`, `consumed_at`, `created_at` and
`updated_at`. Unique secret hash and indexes `(status, expires_at)` and
`(operation_public_id, created_at DESC)` enforce exact single use. Raw tokens are never stored.

`account_gateway_history` stores a private projection: `public_id`, root operation public ID, action,
state/outcome, source/artifact IDs, descriptor hash, byte count, error code and timestamps. It excludes
raw URL, query, headers and bodies. Index `(created_at DESC, id DESC)` supports bounded history.

Root migration creates only shared tables; vault migration creates only private tables. Schema 49 data
is preserved. A second migration call is idempotent. Cross-role tables are explicitly absent.

## State, approval, audit and privacy

The exact download, verification, installation and enablement machines are normative in
`docs/ONLINE_GATEWAY.md`. State transitions use compare-and-set transactions and append audit events.
Approval expiry defaults to 120 seconds, is account/operation/descriptor-bound and single-use. Consuming
approval creates a process-only permit; database rows never become network capabilities by themselves.

Audit retention, shared cache and private-history rules are defined in the architecture. No prompt,
chain of thought, response body, query string, cookies, auth headers or credentials are stored.

## Network, filesystem and threat controls

`docs/ONLINE_GATEWAY_THREAT_MODEL.md` is normative. Security validation occurs before every DNS
resolution result, connection, redirect, resume and install handoff. Environment proxies and automatic
redirect/decompression behavior are disabled. Files use 0700 directories, 0600 files, exclusive
creation, streaming limits, incremental hashes, `fsync` and same-filesystem atomic rename.

## CLI, web and modes

The command and endpoint lists in `docs/ONLINE_GATEWAY.md` are the required parity surface. Both call
one account-scoped application service. User mode can switch its own inert preference and acquire the
official pinned bundle with explicit approvals. Developer mode alone manages user-pinned sources and
technical quarantine data. Server authorization returns 403 for forbidden developer routes.

No business rule, transition, URL validation or hashing is implemented in JavaScript. Web exposes the
active runtime version and accurate gateway status.

## Compatibility, migration and rollback

Existing offline behavior remains the default; startup, dictionary lookup, local pack inspection and
local bundle installation stay socket-free. Schema 50 preserves schema 49 data and root/vault roles.
Language pack and bundle schema remain 1; skills remain 102. Operational rollback disables gateway
configuration and leaves downloads/history inspectable. Code downgrade after schema 50 is unsupported.

## Acceptance criteria

- Every binding decision and threat has an executable regression test.
- No traffic occurs without a fresh exact approval or from startup/lookup/scheduler/model/skill paths.
- SSRF validation cannot be bypassed by redirects, IPv6, rebinding or library re-resolution.
- Exactly one global download runs and restart performs no automatic resume.
- Correct bytes are verified before a distinct install approval; installed packs are not silently
  enabled.
- Account consent/history cannot cross vaults; shared cache contains only public artifacts.
- CLI/web share the service and authorization; user mode cannot reach developer operations.
- Audit serialization contains no prohibited content.
- Full validation matrix passes, including migration, offline 0.8.8 regressions and loopback bundle.

## Release rejection criteria

Reject for any general/arbitrary URL API; network reference in a model/skill/tutor/planner; automatic
traffic, retry, resume, install or enable; proxy/cookie/auth support; mutable descriptors; missing exact
size/hash; SSRF validation only before the first hop; reusable/cross-account approval; concurrent
downloads; unbounded buffering/extraction; raw sensitive audit data; root/vault leakage; changed pack or
bundle schema; more than 102 skills; CLI/web policy divergence; unvalidated migration; or a default
test that contacts the Internet.
